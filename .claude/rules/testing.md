# Testing policy

- Run focused/relevant tests first; suppress successful-test noise where possible (`py -3 -m unittest discover -s tests -b`).
- Full Python suite (`tests/`) is required at final checkpoints and commit-ready validation; it also runs automatically in GitHub CI on every PR and on push to master ("CI Test Gate", `.github/workflows/ci-tests.yml`), alongside the three Node contract tests under `tests/js/`.
- `tests/` DOES cover `web/**` — `tests/test_generate_web_i18n_pages.py` (49 tests) covers the i18n generator, NO/EN key symmetry, the `PAGES` guard, canonical/hreflang, `sitemap.xml`, `robots.txt`, noindex and favicon, and asserts that committed `web/en/**` + `sitemap.xml` byte-match a fresh generator run. A `web/**` diff can therefore break the suite: always run at least that file on a web round (`py -3 -m unittest tests.test_generate_web_i18n_pages -b`). An intermediate round whose diff is demonstrably confined to `web/**` may skip the *rest* of the suite, but still run the full suite at the final checkpoint before commit.
- Real, executed browser/E2E coverage exists (Production Workflow V2, #199, P3): `tests/playwright/**` — Playwright specs, a separate runner from the Python `unittest` suite above, never invoked via `discover -s tests` — run automatically on every PR in the "Playwright Critical Browser Gate" (`.github/workflows/playwright-browser-gate.yml`): Chromium + Firefox, desktop 1280x900 + mobile 390x844, NO + EN, served locally from the checked-out PR head (never production), asserting 0 console/page errors for the flows its specs cover. Run it locally with `npm run test:browser-gate` (wraps `playwright test`, config in `playwright.config.js`). This CI gate does not replace manual verification for behavior outside its fixed scope — a broader/exploratory viewport sweep or a physical-device check is still a separate, owner-run pass (see the `web-full-regression` skill) where it adds evidence the gate doesn't already provide.
- Failures always get full, detailed output. Successful runs get a compact summary (counts, not per-test noise).
- Deeper guidance (isolation principles, `AppTest` pattern): [TESTING.md](../../docs/development/TESTING.md).
